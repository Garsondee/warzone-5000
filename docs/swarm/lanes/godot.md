# Lane GODOT: the real front end, a thin presenter over the Rust core

## Mission
When you have succeeded, the owner opens the project in Godot 4.6.2 on their own Windows PC and watches the replay the browser viewer plays: vehicles built at run time from a `RenderRig`, wheels spinning, suspension travelling, the turret yawing while the gun pitches and recoils, chase and orbit cameras, a small HUD, terrain from WORLD. At M2 they drive any vehicle with keyboard or gamepad through the same `Command` the AI uses, running the real simulation, from a Windows package CI builds. Rust decides, Godot presents: about ten coarse bridge calls, no physics, no logic in GDScript. Your first job is to find out whether this works in a cloud session at all (spike S8).

## Acceptance tests (named; transform and image sentences)
- D1 `wheel_spin_positive_rolls_the_top_of_the_wheel_toward_minus_z`: the rim point (0, R, 0) spun by theta lands at (0, R cos theta, -R sin theta), 1e-6.
- D2 `turret_yaw_swings_the_muzzle_left_gun_pitch_raises_it_and_recoil_slides_it_rearward`: muzzle (0, 0, -L): yaw psi gives (-L sin psi, 0, -L cos psi); pitch phi gives (0, L sin phi, -L cos phi); recoil x adds x to z.
- D3 `steer_positive_turns_the_wheel_left_and_travel_positive_lifts_the_hub_along_bump_dir`: forward (0, 0, -1) steered by delta is (-sin delta, 0, -cos delta).
- D4 `every_joint_coordinate_drives_exactly_one_node_and_a_frame_survives_the_bridge_encoding`: round trip to f32 precision; joint count equals `joint_count`.
- D5 `quaternion_components_cross_the_bridge_in_godots_xyzw_order`: `Quat::from_yaw(pi/2)` becomes (0, sin 45, 0, cos 45) and sends (0, 0, -1) to (-1, 0, 0).
- D6 `interpolation_takes_the_short_arc_across_the_pi_wrap_and_halfway_is_the_midpoint_pose`: spin 3.0 to -3.0 passes through pi, not 0; yaw 0 to 90 degrees halfway is 45 (slerp); positions lerp.
- D7 `seeking_clamps_at_both_ends_and_is_idempotent`.
- D8 `scene_triangle_count_equals_the_render_rig_triangle_count`: on the arrays handed to Godot.
- D9 `terrain_vertices_equal_the_world_height_and_the_speed_hump_peaks_at_0p10_m`: `BumpStrip::standard()` has a half-sine hump of 0.10 m at z = -40; sample at 0.1 m (a 0.8 m hump is invisible to a 1 m grid).
- D10 `chase_camera_settles_on_its_offset_and_trails_a_constant_speed_vehicle_by_speed_times_time_constant`: the lag of first-order smoothing on a ramp.
- D11 `screenshots_at_two_times_differ_where_the_wheels_and_turret_are_and_a_repeat_is_identical` (needs S8): mean absolute difference over the vehicle region above a threshold.
- D12 `the_extension_builds_and_loads_on_linux_and_windows`: build the `cdylib`; headless Godot loads it and prints the bridge version.
- D13 (M2) `steer_right_key_gives_command_steer_plus_1_and_the_truck_turns_toward_plus_x`: the yaw sign is the classic bug.

## Theory to explain in docs/theory/godot.md
Why presentation is separated from simulation: the sim writes an animation cache (a replay, like an Alembic or USD point cache) and the engine only plays it, so one run can be watched in a browser, in Godot and in a test; the bridge is coarse because a call per node per frame is like a draw call per triangle. Forward kinematics of the node tree: `world = parent * rest * joint(q)`, axis in the parent frame, the chain order travel, steer, spin (swap steer and spin and the wheel steers about its own axle). Interpolation: lerp positions, slerp rotations, shortest-arc angles, render rate against sim rate; the wagon-wheel effect is aliasing. Conventions: Godot's frame is ours, and quaternion order is the one trap.
